# 开门响应验收 · 2026-11-07

实现提交：`d93b27e`，基线：`779168f`。保留原有粉笔黑板界面，此改动不涉及界面配色或素材。

普通未锁门收到玩家操作后，客户端立即开始有限的门扇预动，最多转至完整行程的 45%。服务器仍决定门是否打开；确认前实际门状态和碰撞保持关闭。服务器对成功开关立即广播门状态，不再等待下一次 50 ms 快照；对已知门的拒绝立即回复实际状态。拒绝、650 ms 超时、断网、淡出或场景销毁会取消预动。开门声和触感仍在服务器确认后触发。

## 实测

通过真实 TCP 代理分别在两个方向增加 75/125 ms 延迟，得到 150/250 ms RTT。桌面使用真实 E 键，手机使用触屏辅助交互按钮；每种条件执行 5 次开关，另一个真实浏览器玩家确认开关同步。下表为中位数（ms）。

| 设备 / RTT | 首个可见门扇动作，前 → 后 | 门达到可通行门槛，前 → 后 |
| --- | ---: | ---: |
| 桌面 / 150 ms | 208.3 → 6.7 | 391.1 → 189.9 |
| 桌面 / 250 ms | 306.2 → 7.9 | 489.7 → 275.7 |
| 手机 / 150 ms | 182.2 → 14.3 | 377.1 → 199.3 |
| 手机 / 250 ms | 282.4 → 14.8 | 481.4 → 281.7 |

前后各 4 组均通过；页面错误、位置纠正和未确认门跨越碰撞门槛均为 0。使用 ANGLE Metal / Apple M4，实际渲染约 4.8 万（桌面）或 5.3 万（手机）三角形。基准通过开发调试定位至同一真实门并隔离 NPC 伤害，用于比较门响应，不作为自然游戏流程验收。
