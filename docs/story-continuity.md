## 状态与接口

`game/shared/story.ts` 是纯数据和可测试的个人记录状态；`storySite.ts` 只接受关卡结构子集计算锚点，不导入 Three.js、DOM、服务器房间、谜题模块或关卡注册表。

| 接口 | 责任 |
|---|---|
| `storyChapter(level, name)` | 同时匹配零基索引和当次真实 definition 名称；当前未来索引会回落 L4，不能仅凭索引打开未来文案 |
| `StoryState.enter(level, name, seed)` | 建立本次章节上下文；同一上下文重复消息不重复建档，新的尝试不保留当前章完成确认 |
| `StoryState.readNote(fragmentId?)` | 只摘录当前章的一处现场文字；无参数兼容主碎片，未知 id 无效，每章每 id 去重 |
| `StoryState.receive(message, myId)` | 观察当前房间下行事实；L1 楼梯钥匙、L2 已安装三保险丝、L3 本人的四步门序、L4 已停播分别确认，其他关卡消息不代替当前机关 |
| `StoryState.model()` | 只提供当前章引子、真正走过的上一段回顾、本人摘录和已发生的观察；本章机关确认后，顶部提示复用本章已确认文案，重来清确认后恢复初始引子；展示层不导入完整目录自行解锁 |
| `storySites(level, definition)` | 返回当前真实 L1–L4 的碎片 id、正文、样式、坐标与朝向；`storySite()` 保留主碎片兼容入口 |
| `canReadStory(site, feet, yaw, visible)` | 与现场交互共用 `ACT_REACH` 的 2 米距离，并检查正确楼层、文字正面、水平视线 120° 和无遮挡；调用者必须传入本人的最新正常状态服务器快照，不能用预测身体、自由相机或队友替本人读 |

`StoryEntry.kind` 区分现场摘录 `note`、实际听到的 `broadcast`、进展观察 `confirmed` 和跨章回顾 `recap`。前两者是不同来源的发现；后两者不是未读纸条的替代品。记录来源均使用游戏内语言，不向玩家展示服务器、快照或协议术语。

跨章回顾需要两个条件：识别当前章的成功淡出 `restart:false`，以及同一房间随后加载严格相邻且名称正确的下一章。单独淡出、首次加入后章、跳号、未知名称、同章换 seed、重来、开放章节结束，都不补写前章经历。重复同房间消息保留记录；不同房间清掉阅读、进展及候选转场。重来保留读过的文字和听过的片段，清当前机关确认，不因此写出通关。

阅读与查看记录都不写共享背包，不发机关完成消息，不改变怪物、出口、种子或队友进度，也不暂停世界。未读、重复读、关闭面板、同伴先读，都不是额外通关条件。本次浏览器会话结束后不承诺持久保存。
