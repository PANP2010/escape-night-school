本切片基于 `57a05ea537a25f9ac470c98dc863aa58601e3b40`，仅接入服务端导演，不修改角色074步速、动作、台词、语音或捕获展示。捕获过场由 capture 通道负责；本树提交后由集成代理合并、全量检查并部署。

## 原行为量化

使用真实校园导航、碰撞与 WardenAI，房间先进入大厅，再由房主发送 start；每场运行 180 秒、20 TPS、两名玩家，只关闭 L2 值日生以隔离角色074。以下是服务端权威仿真，不是浏览器游玩或真人测试。

| 场景 | seed 1 首追 | seed 2 首追 | seed 3 首追 | 180 秒追逐次数 |
| --- | ---: | ---: | ---: | --- |
| L1 原地 | 79.80 秒 | 109.30 秒 | 58.50 秒 | 各 2 次 |
| L2 原地 | 51.30 秒 | 50.20 秒 | 41.75 秒 | 各 3 次 |

seed 1 的正常走路场景：L1 首追 73.20 秒、2 次追逐；L2 首追 30.80 秒、3 次追逐。分别接受 1953 / 1317 次移动输入，非强制纠正均为 0。原版追逐可在约 27 秒后再次发生；换关前后还可在 20 秒内连续触发自然跳闸。

原始证据、方法和临时量化脚本保留在本树 `game/test-results/tension-head-baseline.json`、`tension-quantification-method.md`，不提交生成证据。

最终版本使用相同方法复验：L1 三种子首追 41.10 / 52.45 / 45.05 秒，L2 为 51.30 / 50.20 / 41.75 秒。六场相邻追逐间隔为 73.00–85.20 秒，中位数由原版 32.90 秒变为 75.53 秒，目标均交替。两个正常走路场景合计接受 4320 次输入，非强制纠正为 0；不将原地或预设走路路径当作真人逃脱证据，逃脱另由真实 WS 检查。

## 接线与范围

- 每个 Room 独立持有纯 `TensionDirector`，使用房间 tick 和独立种子；追逐结束后安排 20–30 秒完全喘息，有合适队友时轮换目标。喘息后可听声调查，新自然追逐仍等到距上次开始 60–75 秒的期限；首次自然遭遇与显式调试召唤保留。
- 平静过久时通过已有 `hear()` 安排真实调查，选取距玩家 6–13 米、视线清楚且路线可步行的位置；沿途仅近距离打开未锁门，不传送怪物。
- 调查使用独立安全图；巡逻保留原节点编号，只剔除穿越锁门、区域门的边，出生点位于玩家可达分量，未锁门在近距离真实打开。玩家引导图保留。图按房间、关卡和锁门状态缓存，换关失效。
- 关门或目标离房结束追逐时，导演先消费结束事件，防止同一 tick 改追队友。喘息期间不感知猎物，已开始的调查可以走完。
- 自然跳闸的随机与追逐触发共用至少 45 秒冷却，换关不清空。普通语录、值日生眨眼、手动 debug power 和捕获展示沿用各自规则。

## 验证与集成

所有 typecheck / vitest / build 均经 `parallel_sprint.py gate heavy`，Vitest 使用 `--maxWorkers=1`；不运行全量 `npm run check`。真实 WS 验收使用 `python3 tests/run-tension-ws.py`，只占本树 4421 端口、关闭自己启动的服务器；无需浏览器与音频。

类型检查与服务端构建通过；15 个相关测试文件共 133 项通过，包括导演、真实校园碰撞、出生与复活保护、L3/L4、广播、门和大厅生命周期。

最终真实 WS 验收运行 122.60 秒，四项全部通过：

- 抓捕后通过真实交互救起，最少 20 秒内两名玩家都没有连抓。
- 跑步完整通过两个服务器确认的路点，追逐中由转角打断实际视线，正常存活且非强制纠正为 0。
- 下一次自然追逐在 75.70 秒后转向队友，没有再次调试召唤。
- 两房各实际发生两次自然跳闸，间隔分别 75.70 / 87.20 秒；同房 256 个 tick 的快照完全一致，成员、目标没有跨房泄漏。角色074单 tick 最大位移 0.238 米，未发现传送。

最终原始证据在 `game/test-results/tension-ws.json`；自启 4421 服务器已由脚本退出并关闭。未生成或提交客户端构建与依赖。

没有录制视频，也没有 Gemini 外部评分。采样覆盖 L1/L2 的三个种子与两个预设移动路径，不构成任意玩家位置都能在 90 秒内被追逐的证明；不可达或隐蔽目标不会触发穿墙或传送补偿。集成时保留其他通道的 `warden.ts` 步速、形态和 capture 接线，再运行全量检查和部署。
